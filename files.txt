■ HTMLページ
index.html          サイトのトップページ。計画概要・現在の状況・今後のスケジュールをまとめたホーム画面。下部の「最新の動き」以降は毎日自動更新されるコーナー。
about.html          学校再編計画の背景・目的・対象校・新校名などを詳しく解説する計画概要ページ。
schedule.html       フェーズ別タイムライン・月別カレンダー・主要イベント一覧を掲載するスケジュールページ。
council.html        市議会での審議内容（令和8年第1回定例会）を整理した議会審議ページ。
community.html      地域協議会・区長会への報告経緯と住民意見をまとめた地域協議会ページ。
voices.html         faq.html へ統合したあとの移動案内（noindex。共有済みリンクのために残している）。
faq.html            よくある質問と賛否の声。Q&A（アコーディオン）・賛成反対中立の声・パブリックコメントの論点。
bus.html            スクールバスの運行予定・対象校・費用負担などを解説するスクールバス情報ページ。
clubs.html          校区内の地域クラブ・課外活動と各校の部活動を学校ごとに紹介するページ。部活動の地域移行の説明つき。
map.html            再編対象の各学校の位置を地図で確認できる学校マップページ。
nationwide.html     全国の廃校数・国が示す学校規模と通学の基準・2026年8月の手引改訂を整理した「全国の動き」ページ。
review.html         計画の検証と提案のページ（要点）。検証の核心10項目と提案の核心10項目（教育の質5・東部の子どもを増やす5）、確認できなかったこと（要点側）。各項目は analysis.html の根拠へリンク。当サイトの見解を含む。
analysis.html       深掘り検証のページ（2026-10-30 に review.html から分割）。3部構成：計画そのもの（読み取れないこと・だれが決めるか・都市計画の動き）、教育の質、子どもの数（施策の年表・県と国・本来どうすべきだったか・子どもを増やす提案・高校段階）と、確認できなかったこと24項目。根拠のカードから要点へ戻る札は js/main.js の REVIEW LINKS。当サイトの見解を含む。
img/illust/*.svg    サイト全体の挿絵（2026-10-31〜。全ページ）。文字を含まない飾り（alt=""）で、説明の文字は辞書から流す。下絵は Claude Design。校舎は古く描かない（building.svg）。
site.html           このサイトについて（2026-10-30 に index.html から移した）。紹介用画像・アプリとして使う・広める・ご意見の送り先・閲覧数の集計。
404.html            存在しない URL を開いたときに GitHub Pages が返すページ。主なページと12言語への入口（noindex・sitemap 対象外・共有欄なし）。深いパスでも崩れないよう <base href="/"> を持つ。

data/events.json            カレンダーイベントデータ（日付キー＋12言語ラベル）。schedule.htmlのカレンダーが実行時にfetchして描画。イベントの追加・変更はこのファイルを編集する。

data/school_news.json       再編対象8校の公式ホームページ新着記事（自動生成・手編集不可）。トップページのコーナーが実行時にfetchして描画。
data/community_events.json  地域協議会イベント案内（自動生成・手編集不可）。community.htmlのコーナーが実行時にfetchして描画。
                            市サーバへは行かず、official_pages/のスナップショットから組み立てる。篠岡地区の5協議会分はshinooka=trueで先頭表示。
                            見出し・掲載日・記事URL・冒頭1文の引用のみを保持する。checked_idsは確認済み記事IDの記録で、同じ記事を二度取りに行かないためのもの。
data/site-updates.json      このサイト自身の更新履歴（手動管理）。トップページ最下部の「サイトの更新履歴」が実行時にfetchして描画。新しいものを配列の先頭に追加する。
data/bus_area.kml           bus_map.geojsonと同じ図形のKML版（通学区域2つ＋対象エリア3片＋新設2校）。Googleマイマップに読み込んでGoogleマップ上に重ねるためのもの。bus.htmlからダウンロードリンクを張っている。
data/bus_map.geojson        bus.htmlの地図が描画する全データ（手動生成）。出典が3系統で精度が違う：通学区域（桃花台東/西）は国土数値情報「小学校区」（国土交通省）＋国勢調査の町丁境（総務省統計局）から合成した正確なもの、
                            対象エリアは「学校再編だより」vol.6の図を目視トレースして通学区域の内側に切り詰めた非公式の近似（飛び地3片）、道路・地区名・施設はOpenStreetMap（ODbL、出典表示が必要）。

data/community_actions.json 地域で行われている催し・取組（手動管理）。community.html「地域の取組」（地域協議会イベント案内の直下）と、index.html「最新の動き」の同名コーナーが実行時にfetchして描画。市の公式情報でも報道でもなく主催者自身の発信であり、計画の内容・数値の根拠には使わない。badgeで市民有志（citizen）と地域協議会（council）を書き分ける。source_urlはauto_gates.pyのPERMITTED_INSTAGRAMにあるアカウントのみ。

data/tobu_actions.json      東部まちづくりの取組（自動生成・手編集不可）。community.htmlとindex.htmlの「地域の取組」欄の下半分が実行時にfetchして描画。
data/child_estimate.json 東部地域の0〜17歳の推定の係数（自動生成・手編集不可）。index.htmlの「いまの状況」の下の枠が実行時にfetchし、閲覧日の推定値を小数第1位まで計算して表示。
data/official_pages/population/ 市の人口統計（指定区別年齢別男女別人口統計表・人口世帯表）のうち東部の町字の行（自動取得・手編集不可・古いものも消さない）。

■ GitHub Actions
.github/workflows/fetch-news.yml    市公式サイトから最新お知らせを定期取得してnews.jsonと本文スナップショットを更新し、本文変更時はIssue起票→AIによる修正案の起案→機械検証→監査AI→自動マージまで行うワークフロー定義。
.github/scripts/fetch_news.py       市公式サイトをスクレイピングしてお知らせ情報の抽出・整形と各ページ本文のスナップショット保存を行うPythonスクリプト。
.github/scripts/fetch_pdf_docs.py   市の掲載ページに添付されたPDFから本文テキストを抽出し、official_pages/<群>/ に保存するスクリプト（SOURCESの表で対象を宣言）。
                            現在の対象は newsletters/（学校再編だより）、setsumeikai/（説明会の質疑応答・意見提出シート）、pubcom/（パブコメの意見と市の考え方）、gikai/（市議会だより）。
                            掲載ページのHTMLはfetch_news.pyの取得結果を使い回し、PDFは未取得のものだけ落とす。fetch_news.pyの【あと】に実行すること。
                            取り込むのは出典であって原稿ではない。市の文面をそのままページに貼らず、当サイトの言葉で書き直すこと。
.github/scripts/fetch_schools.py    再編対象8校のホームページ（komaki-aic.ed.jp）を巡回し、各校の最新記事をschool_news.jsonに保存するスクリプト。
.github/scripts/build_community_events.py 地域協議会イベント案内をスナップショットから抽出してcommunity_events.jsonを生成するスクリプト。市サーバへのアクセスなし。fetch_news.pyの【あと】に実行すること。
.github/scripts/build_tobu_actions.py 東部まちづくりの取組一覧（tobu_actions.json）をスナップショットから組み立てるスクリプト。市サーバへのアクセスなし。fetch_news.pyの【あと】に実行すること。
.github/scripts/fetch_population.py 市の人口統計の索引を見て、新しい表が出たときだけ東部の行を取り出して data/official_pages/population/ に保存するスクリプト。
.github/scripts/build_child_estimate.py population/ の保存データから child_estimate.json を作るスクリプト（市サーバへのアクセスなし、--check あり）。fetch_population.pyの【あと】に実行すること。
.github/scripts/build_toshikeikaku.py 都市計画課のスナップショットから東部に関係する掲載（toshikeikaku_east.json）を組み立てるスクリプト。市サーバへのアクセスなし。fetch_news.pyの【あと】に実行すること。
.github/scripts/check_contacts.py   data/contacts.jsonの連絡先を市・県・国の公表ページと突き合わせるスクリプト。--fixで電話・FAX番号だけ自動修正（部署名は翻訳があるので手で直す）。exit 0=一致/3=食い違い/1=エラー。
.github/scripts/check_reach.py      週1回の利用状況レポート（GoatCounter の閲覧数・はてなブックマーク数・Bluesky の公開検索）。X・Instagram 等は取りに行かずリンクだけ載せる。数字はコミットしない。
.github/scripts/check_links.py      外部リンクの死活確認。Instagram・Facebook・共有ボタンの送り先・Googleマップは見ない。記録は data/link_check.json。exit 0=問題なし/3=切れあり/1=エラー。
.github/scripts/term_rules.py       訳語のゆれの検査（data/term_rules.json の規則で辞書・見出しの訳・予定の名前・地域の取組を照合）。auto_gates.py check 18 と headline_i18n.py が使う。
.github/scripts/record_fetch_status.py 毎日の巡回の最後に、取得元ごとの確認日時と成否を data/fetch_status.json に書く。
.github/scripts/map_targets.py      変更された公式ページのスラッグをsite-facts.jsonで引き、サイト内の更新候補箇所をMarkdown出力するスクリプト（Issue本文生成用）。
.github/scripts/build_page_dicts.py  data/i18n/pages/ を生成する。辞書やHTMLのdata-i18nを変えたら実行してコミットすること。--check で鮮度検証のみ。
.github/scripts/build_qr.py         回覧板シートと共有欄の「QR」ボタンが使うQRコード（qr/<ページ>.<言語>.svg）を生成する。segnoが必要（pip install segno）。--check で鮮度検証のみ。
.github/scripts/auto_gates.py       自動更新のガードレール検証（編集範囲・スキーマ・ja/enキー一致・こどもモード1行の長さ・ページ別辞書の鮮度・外部リンク規則・出典実在チェック）。exit 0=合格/3=変更なし/1=不合格。
.github/scripts/auto_report.py      自動更新のPR本文・事後報告コメントをevidence.json/verdict.jsonから生成するスクリプト。
.github/workflows/check-contacts.yml 毎週1回、担当部署の連絡先を公表ページと照合するワークフロー定義。番号の変更は自動コミット、部署名の変更はIssueで知らせる。
.github/workflows/check-reach.yml    毎週月曜 7:10 JST に check_reach.py を回し、メール（だめなら Issue）で届けるワークフロー定義。Secret GOATCOUNTER_TOKEN が無ければ閲覧数は省く。
.github/ISSUE_TEMPLATE/feedback.yml  読者の声の窓口（index.html#feedback）の Issue フォーム。公開されること・個人情報を書かないことを冒頭に明記。
.github/workflows/check-links.yml    毎週1回、サイトが張っている外部リンクが開けるかを確かめるワークフロー定義。2週続けて開けないURLをIssue（🔗）で知らせる。自動では直さない。
.github/workflows/feature-ideas.yml 毎朝1回、このサイトに足すとよさそうな機能をAIに考えさせてメールで届けるワークフロー定義。サイトのファイルは変更しない。
.github/workflows/translate-headlines.yml 取得ワークフローの完了後、新しく入った見出しだけをAIで9言語に訳し、機械検証してheadline_i18n.jsonに取り込むワークフロー定義。
.github/scripts/headline_i18n.py    見出し翻訳の下ごしらえと検証（pending＝訳の無い見出しを書き出す／apply＝AIの下書きを検証して取り込む／prune＝古い訳を落とす）。
.github/scripts/send_mail.py        件名と本文ファイルを受け取ってSMTPでメールを1通送るスクリプト。宛先は1件のみ（未指定ならSMTP_USER宛て）。設定が無ければexit 2（呼び出し側はIssueに切り替える）。
.github/scripts/ideas_digest.py     アイデア案（auto_ideas/ideas.md）から見出しを拾い、履歴への追記とメール件名の生成を行うスクリプト。
auto_ideas/history.json             過去に出した新機能アイデアの見出しの記録。同じ案を繰り返さないために起案AIが読む。本文はメール（とActionsのアーティファクト30日）にのみ残る。

■ 設定・その他
.claude/settings.local.json    Claude Codeのプロジェクト固有の権限・設定を記述するローカル設定ファイル。
CONTRIBUTING.txt               コンテンツ管理チェックリスト。外部リンク制限・i18nルール・日付連動の自動表示・こどもむけ等の運用ルールと検証手順を記載。
README.md                      プロジェクト概要・ページ構成・対応言語・ローカル開発手順を説明する公開用READMEファイル。
CLAUDE.md                      Claude Code向けの開発ガイド（英語）。i18n仕様・検証コマンド・制約事項を記載。
CLAUDE_ja.md                   CLAUDE.mdの日本語説明ファイル。日本語話者向けにCLAUDE.mdの内容を解説。
files.txt                      本ファイル。サイト構成ファイルの一覧と説明を手動管理するインデックス。
