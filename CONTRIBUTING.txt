──────────────────────────────────────────────────────
【ルール2】翻訳ファイルは JSON。壊れると言語切り替えが止まる
──────────────────────────────────────────────────────

■ 前提（重要・以前と変わっている）
  翻訳テキストは data/i18n/<lang>.json にある。
  js/i18n.js は JSON を fetch して当てるだけで、翻訳文そのものは持っていない。

  ★ かつて「i18n.js のシングルクォート内のアポストロフィを \' でエスケープする」
    というルールがあったが、JSON 化された現在は誤り。JSON ではアポストロフィは
    そのまま書いてよく、むしろ \' と書くと不正なエスケープで構文エラーになる。
      OK: "It's the school's policy"
      NG: "It\'s the school\'s policy"   ← JSON では構文エラー

■ JSON が実際に壊れるパターン（この4つを疑う）
  (1) 値の中の素のダブルクォート     "say "hi""      → \" にする
  (2) 末尾カンマ                     {"a": "1",}
  (3) 値の中の生の改行               複数行に分けて書いてしまった
  (4) 単独のバックスラッシュ         "C:\path"       → \\ にする

■ 壊れたときの挙動
  ja 以外が壊れた場合  … その言語の fetch が失敗し、ja だけで表示される
                         （i18n.js の catch で DEFAULT に落ちる）。気付きにくい。
  ja.json が壊れた場合 … 全言語が表示できず、HTML に直接書かれたフォールバック
                         文言のまま表示される（showPage のみ実行）。

■ チェック方法（ターミナルで実行・9ファイルまとめて）
  python3 -c "
  import json, glob, sys
  bad = 0
  for f in sorted(glob.glob('data/i18n/*.json')):
      try:
          json.load(open(f, encoding='utf-8')); print('OK  ', f)
      except Exception as e:
          bad += 1; print('NG  ', f, e)
  sys.exit(1 if bad else 0)
  "
  → 全て OK であれば問題なし。編集した言語だけでなく必ず9ファイル全部を通す。


──────────────────────────────────────────────────────
【ルール3】多言語キーを追加する際のフォールバック
──────────────────────────────────────────────────────

■ 仕組み（3段フォールバック）
  js/i18n.js は ja・en・対象言語の JSON を fetch し、
  Object.assign({}, ja辞書, en辞書, 対象言語辞書) でマージしてから当てている。
  対象言語に無いキーは【英語】が出る。日本語まで落ちるのは en にも無いときだけ。
  英語を挟むのは、トルコ語やビルマ語を選んだ人にとって日本語より英語のほうが
  読める可能性が高いため。ja と en は全キー揃っているので、全訳済みの言語では
  表示は一切変わらない。

  こどもむけモード（日本語のみ）は ja-kids.json を ja の上に重ねる：
  Object.assign({}, ja辞書, ja-kids辞書)。ja-kids に無いキーは通常の日本語になる。

  ★★ こどもむけは「漢字を開く」だけでは足りない。1文を短くすること。
     読みやすさを決める変数は 2つある。表記（漢字かひらがなか）と 1文の長さで、
     効くのは後者のほうが大きい。しかも漢字をひらがなに開くと文字列は「伸びる」ので、
     文を割らずに開くだけだと、小3の作業記憶にはむしろ元の文より重くなりうる。
     （2026-08-13 の点検では、漢字率は 44.9%→15.4% と十分に下がっていた一方、
       文の数が ja とまったく同じキーが 89% あり、1文の長さがほぼ動いていなかった。）

     ・目安：1行 45モーラ以下。理想は 30前後（小3の目安）。上限 65 は auto_gates.py の
       チェック4が機械的に弾く。
     ・「1行」＝ <br> / </li> / </p> と 。！？：| で切れる、読者が実際に目にする単位。
       箇条書きの各項目は 1行と数える（長い <li> の並びは長文ではない）。
     ・長さは【モーラ換算】で測る（漢字≒1.9・仮名≒1）。ひらがなに開くと文字数が
       増えるため、文字数のままでは ja と比べられず、簡易化の効果を判定できない。
     ・割れないものは割らなくてよい。学校名の列挙・部署名・電話番号など、
       固有名詞が理由で長い行は、無理に切ると かえって読みにくくなる。
     ・事実（数字・日付・学校名）は絶対に変えない。割るのは文であって内容ではない。

■ 対応言語（10言語）
  【全キー翻訳済み】ja / en / pt / vi / tl / es / zh / id / tr / my
  ＋ ja-kids（こどもむけ。言語切替の選択肢ではなくトグル）

  ★ 2026-08-13 に tr / my が全661キー揃ったので、10言語すべて全訳済みになった。
    i18n.js の PARTIAL 配列は空。「未翻訳部分は英語で表示されます」の帯も出ない。
    今後あらたに部分翻訳の言語を足すときは、i18n.js の PARTIAL と
    auto_gates.py の PARTIAL_LANGS の両方にコードを入れること。
  ★ 言語を増やすときに直す場所：
      data/i18n/<lang>.json 新規作成 / i18n.js の LANGS・langAttr・PARTIAL /
      全10ページの <option> と hreflang（?lang=<コード> 付きの実URL）/ sitemap.xml /
      footer_langs（全言語）/ auto_gates.py の PARTIAL_LANGS /
      main.js の KomakiLang の LANGS・CAL_LOCALE_MAP・各インラインラベル辞書
  ★ events.json のイベントラベルは【10言語必須】（auto_gates.py の LANGS）。
    部分翻訳の言語を足したときだけ PARTIAL_LANGS に入れて必須対象から外す。

■ 最低要件
  新しいキーを追加する際は ja（日本語）と en（英語）に【必ず両方】記載する。
  他の6言語（pt / vi / tl / es / zh / id）は未記載でも英語フォールバックが
  適用されるが、できれば随時追加すること。
  こどもむけで言い回しを変えるべきキーは ja-kids.json にも入れる。

  ★ ja と en のキー集合は完全に一致していなければならない。
    js/i18n.js は非日本語表示で ja.json を取得しない（en が全キーを持つ前提で、
    毎回 gzip 約23KB の無駄な転送をやめたため）。en に入れ忘れたキーは、
    その言語の閲覧者には HTML に直書きされた日本語のまま表示される。
    auto_gates.py のチェック3が機械的に検証するので、片方だけの追加は落ちる。

  ★★ 辞書を変更したら【必ず】ページ別辞書を作り直すこと。
        python3 .github/scripts/build_page_dicts.py
     i18n.js は data/i18n/pages/<ページID>.<言語>.json（そのページが使うキーだけ）を
     取りに行く。作り直しを忘れると、無いページは 404 で全体辞書に落ちるので無事だが、
     【古いページ別辞書は古い文面を 200 で返す】ため実行時には救えない。
     auto_gates.py のチェック5が --check で検出して落とす。
     data/i18n/pages/ を手で編集しないこと（生成物）。
     ページに新しく data-i18n を書いたときも同様に作り直しが必要。

■ キー追加の注意
  - キー名は既存の命名規則に従う（ページ名_セクション名_種別）
  - HTMLを含む値は data-i18n-html 属性で呼び出す
    （data-i18n は textContent を書き換えるので、値のタグが消えて表示が壊れる）
  - テキストのみの値は data-i18n 属性で呼び出す
  - aria-label は data-i18n-aria
  - ページの <title> と OG/Twitter メタは meta_title_<ページID> /
    meta_desc_<ページID> というキー名で自動的に差し替わる（ページIDは
    ファイル名から .html を除いたもの。index.html なら meta_title_index）

■ チェック方法（HTMLで使っているキーが ja.json にあるか）
  python3 -c "
  import json, re, glob, collections
  ja = json.load(open('data/i18n/ja.json', encoding='utf-8'))
  pat = re.compile(r'data-i18n(?:-html|-aria)?=\"([^\"]+)\"')
  miss = collections.defaultdict(list)
  for f in sorted(glob.glob('*.html')):
      for k in set(pat.findall(open(f, encoding='utf-8').read())):
          if k not in ja: miss[f].append(k)
  print('未定義キー:', dict(miss) or 'なし')
  "

【ルール5】日付連動の自動表示（現在日付を反映する箇所）
──────────────────────────────────────────────────────

サイトには「現在日付に応じて表示が自動で変わる箇所」がある。
これらは js/main.js が閲覧者のブラウザ上で毎回計算するため、
手動更新は不要だが、データの持ち方を間違えると正しく動かない。

■ 「最終更新: 〜」表示について
  - 見出し「現在の状況」「主要イベント一覧（公式情報）」の直下にある
    <p class="section-updated"> に、配信ファイルの Last-Modified（GitHub Pages
    では再デプロイ時刻）から最終更新日を多言語で自動表示する。
  - これは「サイトの最終デプロイ日」であり、そのセクションの編集日と厳密には
    一致しない（≒ 直近の push 日）。手動で日付を書く必要はない。
  - ★ 見出しテキストに固定の日付を書かないこと（例：「現在の状況（2026年5月時点）」）。
    以前ハードコードされていたが、陳腐化するため廃止し自動表示に置き換えた。

■ スケジュール／状況の項目を追加・編集するとき
  - 各イベント項目（.event-item）・状況項目（.status-item）には
    data-event-date="YYYY-MM-DD" を正しく設定する。現在日付がこれを過ぎると
    自動的に「完了」表示（バッジ／スタイル）になる。
  - 複数日にまたがるイベントは「終了日」を data-event-date に入れる
    （例：6月の保護者説明会6回 → 最終日 2026-06-29）。
  - 恒久的に過去・進行中のものは、HTML 側で done / current クラスを直接付ける
    （data-event-date なしでよい）。
  - 状態バッジの文言は event_status_done / event_status_current /
    event_status_upcoming キー（全言語に記載済み）。新しい状態を作らない。
  - 地域協議会（支え合い協働推進課）のイベントが公式に掲載され、篠岡地区5校区
    （陶・篠岡学区・大城・光ヶ丘・桃ヶ丘）のものであれば、community.html だけで
    なくスケジュールにも入れる。data/events.json（10言語）＋ schedule.html の
    主要イベント一覧、開催前なら index.html の「今後のスケジュール」バーにも追加。
    他学区（小牧小・本庄小・小木小など）のイベントは対象外。

  - 月別カレンダーに予定を足すときは data/events.json の events オブジェクトに
    "YYYY-MM-DD": {ja, en, pt, vi, tl, es, zh, id, tr, my} 形式で追加する（10言語すべて必須。
    初期表示月の範囲も自動で追従）。js/main.js が実行時に fetch して描画するので、
    main.js 側は編集しない。

  - トップページ「今後のスケジュール」バー（index.html の .upcoming-item）は
    data-event-date ではなく data-expires="YYYY-MM-DD" を使う。その日を過ぎると
    項目が自動で非表示になる（全項目が消えるとバー自体も非表示）。
    ・文言は upcoming_dateN / upcoming_nameN キー（全言語）。日付の見た目は各言語の
      書式に合わせる。ja-kids は日付キーを持たず ja にフォールバックする。
    ・直近の予定は「6会場まとめて1行」ではなく、schedule.html・カレンダーと同じ
      個別日程で記載し、内容（日付・会場・data-expires）を一致させること。
    ・期限切れで恒久的に非表示になった項目は、HTML と i18n キーごと削除してよい
      （経緯は schedule.html の主要イベント一覧と「現在の状況」に残る）。

■ ★ トップ冒頭「いまの状況」枠（.now-bar）だけは自動化されていない
  - index.html のヒーロー直下にある枠で、現況を「1文」で伝える。
    このルール5で挙げた他の表示（完了バッジ・カレンダー初期月・最終更新）が
    すべて日付から自動計算されるのに対し、ここだけは手書きの文章である。
  - そのため、放置すると最も早く古びるうえ、トップ冒頭なので古さが最も目立つ。
  - 使うキー（全10言語＋ja-kids を必ず揃える）：
      now_label … 枠のラベル「📌 いまの状況」。ほぼ変えない
      now_text  … 現況を1文で要約。data-i18n-html なので <strong> が使える
      now_asof  … その文がいつ時点かを示す月（例「2026年8月時点」）
      now_more  … 「現在の状況」セクション（#status）へのリンク文言
  - 更新すべきとき：予定していた行事が終わった／新しい資料や決定が公表された／
    次の段階に進んだ、など「状況が動いた」とき。now_text と now_asof を一緒に直す。
  - 更新しなくてよいとき：公式ページの誤字修正・体裁変更など、状況が動かない変更。
  - こどもむけ（ja-kids）の now_text は小学3年生レベルにする（【ルール6】参照）。
    読みやすさを優先し、1文にこだわらず短く区切ってよい。
  - data/site-facts.json では now_bar として登録し default_targets にも入れてある。
    公式ページの変更が検知されると自動更新パイプラインがここを更新候補として扱う。

【ルール6】こどもむけ（ja-kids.json）は小学3年生レベル
──────────────────────────────────────────────────────

■ 方針
  data/i18n/ja-kids.json は「こどもむけ」トグル用の上書き辞書。
  小学校3年生が読める日本語を基準とする。
  - 難しい漢字・熟語はひらがな化、またはやさしい言葉に置き換える
    （例：状況→ようす、運行→バスをはしらせる、議案→あん）。
  - 一文を短く、です・ます調。本サイトはふりがな機能がないため、
    小3で習わない漢字は基本ひらがなにする。
  - 公式の「小学生用」配布資料（市公式サイト）の文体を参考にする。

■ キーが無い場合の挙動
  ja-kids.json にキーが無ければ ja.json（おとな向け日本語）にフォールバック
  する。こどもむけで難しい表記が残っていたら、該当キーを ja-kids.json に追加する。
  ナビ・サブタイトル等の共通キーも対象（例：nav_about, site_sub）。

■ チェック方法
  python3 -c "import json;json.load(open('data/i18n/ja-kids.json',encoding='utf-8'));print('OK')"
  → JSON として有効であることを確認（構文崩れで全こどもむけ表示が壊れる）。
